# Лабораторные 1–4: сортировки на C++17 и Catch2

В репозитории 12 отдельных статических библиотек сортировок и проект unit-тестов.
Решение **SortingLabs.sln** содержит ровно два видимых проекта:
**SortingLibraries** собирает отдельные библиотеки через CMake,
**SortingTests** собирает и автоматически запускает тесты Catch2.
Это проекты-обёртки Makefile: настоящий код отображается в обозревателе,
а компиляцией и зависимостями управляет CMake.

## Структура

```text
sorting/           # Лаба 1: insertion, selection, exchange, bubble, optimized_bubble
  include/         # Отдельный .h для каждого алгоритма
  src/             # Отдельный .cpp для каждого алгоритма
enhanced_sorting/   # Лаба 2: binary_insertion, shaker; лаба 3: shell, quick
  include/
  src/
external_sorting/   # Лаба 4: two_phase_merge, one_phase_merge, natural_merge
  include/
  src/
tests/             # main.cpp, отдельные test_*.cpp, проверки слияния и оптимизаций
third_party/       # Catch2 2.13.10 и его лицензия
visual_studio/     # Два проекта решения Visual Studio
.github/workflows/ # Проверка сборки и тестов на Windows и Linux
```

## Открыть в Visual Studio 2022

1. Установить рабочую нагрузку «Разработка классических приложений на C++»,
   включая MSVC v143, Windows SDK и «Средства CMake C++ для Windows».
2. Открыть `SortingLabs.sln`. Выбрать `Debug | x64`.
3. Нажать «Сборка решения». После сборки тестового проекта все тесты запускаются автоматически.
4. Для запуска через F5 выбрать **SortingTests** запускаемым проектом.

Внешние зависимости скачивать не нужно: Catch2 находится в репозитории.
Каталоги `build-vs/` и `build/` создаются автоматически и исключены из Git.

## Сборка через CMake

Windows, терминал с CMake в PATH:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Debug --parallel 2
ctest --test-dir build -C Debug --output-on-failure
.\build\Debug\SortingTests.exe "[lab4]"
```

Linux / macOS, установленный компилятор C++17:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
./build/SortingTests "[lab4]"
```

Для сборки только библиотек: `cmake --build build --config Debug --target SortingLibraries`.
Чтобы отключить автозапуск тестов: добавить к конфигурации
`-DSORTING_RUN_TESTS_AFTER_BUILD=OFF`. CTest и ручной запуск продолжат работать.

## Использование библиотек

```cpp
#include "insertion_sort.h"
#include "quick_sort.h"
#include "one_phase_merge_sort.h"

std::vector<int> values{5, 2, 4, 1, 3};
sorting::insertion_sort(values);                  // По возрастанию
sorting::quick_sort(values, std::greater<int>{}); // По убыванию
sorting::one_phase_merge_sort(values);           // Обёртка также использует файлы
sorting::one_phase_merge_sort<double>("input.txt", "output.txt");
```

В CMake подключить нужную цель: `target_link_libraries(my_app PRIVATE insertion_sort)`.
Внутренние сортировки поддерживают `std::vector<T>` и пользовательский компаратор.
Компаратор должен задавать строгий слабый порядок. Значения NaN для внутренних
сортировок с обычным `std::less` не поддерживаются.

Определения шаблонов находятся в `.h`, чтобы можно было использовать новые типы
и компараторы. В каждом `.cpp` явно инстанцированы версии для `int` и `double`,
а `extern template` в заголовках обеспечивает их подключение из отдельных библиотек.

## Внешние сортировки

Формат входного/выходного файла: **одно число на строку**; дробная часть — через
точку, пустые строки во входе игнорируются. Поддерживаются арифметические типы,
кроме `bool`; NaN, бесконечности и некорректные числовые записи отклоняются.
Для `double` сохраняется точность обратного преобразования (`max_digits10`).

* Двухфазное простое слияние: распределение серий длины 1, 2, 4, ... в два файла,
  затем слияние обратно в рабочий файл.
* Однофазное простое слияние: четыре вспомогательных файла; пары входных серий
  сливаются сразу попеременно в два выходных файла. На следующем проходе пары
  файлов меняются ролями. Отдельного повторного распределения нет.
* Естественное слияние: выделяются уже упорядоченные серии и попарно сливаются;
  после каждого прохода границы серий определяются заново.

Файловые API читают последовательно, удерживая постоянное число значений в памяти,
и используют O(n) временного места на диске. Vector-обёртка дополнительно хранит
входной/выходной массив в памяти. Временные папки уникальны и удаляются по RAII,
в том числе при исключениях. При некорректном входе существующий выходной файл
не меняется; запись результата начинается после успешной сортировки. Ошибка
финального копирования (например, нехватка диска) не гарантирует сохранности
предыдущего выходного файла. Одинаковый путь входа и выхода поддерживается.

## Тесты

Для каждого алгоритма есть отдельные тесты на пустой массив, один элемент,
отсортированные/обратные данные, дубликаты, `double`, свой компаратор и сравнение
случайных данных с `std::sort` с фиксированным seed. Устойчивые внутренние алгоритмы
проверяются на записях с равными ключами. Для внешних алгоритмов дополнительно
проверяются файлы, нечётное число серий, сохранение исходника, одинаковые пути,
невалидные данные и ошибки путей. Отдельные проверки покрывают слияние серий,
временные файлы и уменьшение числа сравнений в оптимизированных алгоритмах.

Catch2 2.13.10 подключён так же, как в методичке: `CATCH_CONFIG_MAIN` определён
ровно в одном `main.cpp`, тесты используют `TEST_CASE` и `REQUIRE`.
