# SortingCPP — лабораторные 1–4

Учебные реализации сортировок на C++17 и unit-тесты Catch2.

## Индивидуальное задание — вариант 9

Исходный массив: `[7, 17, 9, 3, 13, 1, 16, 10]`.
Результат по возрастанию: `[1, 3, 7, 9, 10, 13, 16, 17]`.

Этот массив используется в основном тесте каждой из 12 сортировок.
Для трёх внешних сортировок он дополнительно проверяется через файловый API.
Алгоритмы остаются универсальными и принимают любые допустимые входные данные.

Запуск только индивидуального варианта после сборки Visual Studio:

```powershell
.\build-native\Debug\Test.exe "[variant9]" -s
```

Тег `[variant9]` выбирает 15 тестов: 12 сортировок вектора и 3 сортировки файла.
Параметр `-s` показывает успешные проверки вместе с результатами.

## Структура

* `Sem1/` — все 12 сортировок: отдельные `.h` и `.cpp`.
* `Test/` — отдельный файл тестов для каждой сортировки и `Test.cpp` с точкой входа.
* `catch2/` — Catch2 2.13.10 и лицензия. Скачивать библиотеку не нужно.
* `SortingLabs.sln` — обычное решение Visual Studio с двумя проектами.

В Visual Studio проект `Sem1` собирает общую статическую библиотеку сортировок,
а `Test` — консольную программу с тестами. CMake дополнительно позволяет собрать
каждую сортировку как отдельную статическую библиотеку, как требуется в задании.

## Запуск в Visual Studio 2022

1. Открыть `SortingLabs.sln` (нужна рабочая нагрузка «Разработка классических приложений на C++»).
2. Выбрать `Debug | x64` и выполнить «Сборка решения».
3. Тесты запустятся автоматически после сборки проекта `Test`.
4. Для запуска через F5 выбрать `Test` запускаемым проектом.

CMake для открытия и сборки этого решения не требуется.

## Сборка через CMake

```sh
cmake -S . -B build-simple -DCMAKE_BUILD_TYPE=Debug
cmake --build build-simple --config Debug --parallel 2
ctest --test-dir build-simple -C Debug --output-on-failure
```

## Сортировки

* Лаба 1: `insertionSort`, `selectionSort`, `exchangeSort`, `bubbleSort`, `optimizedBubbleSort`.
* Лаба 2: `binaryInsertionSort`, `shakerSort`.
* Лаба 3: `shellSort`, `quickSort`.
* Лаба 4: `twoPhaseMergeSort`, `onePhaseMergeSort`, `naturalMergeSort`.

```cpp
#include "insertion_sort.h"

std::vector<int> arr = {7, 17, 9, 3, 13, 1, 16, 10};
insertionSort(arr);
```

Все функции сортируют по возрастанию. Шаблоны находятся в заголовках, чтобы
поддерживать разные типы; в `.cpp` созданы версии для `int` и `double`.

Внешние сортировки используют бинарные файлы: одно значение занимает `sizeof(T)`
байт. Файл нужно читать тем же типом, которым он записан. Это учебный формат для
работы на одной машине, без преобразования в текст. Для `double` используются
конечные числа. Файловые функции читают данные по одному элементу, а функции
для векторов записывают массив в файл и возвращают результат в вектор.

```cpp
writeVectorToFile("numbers.bin", std::vector<int>{7, 17, 9, 3, 13, 1, 16, 10});
twoPhaseMergeSortFile<int>("numbers.bin");
auto arr = readVectorFromFile<int>("numbers.bin");
```

Двухфазная сортировка разделяет и сливает серии; однофазная использует четыре
файла и меняет их роли; естественная находит уже упорядоченные серии и сохраняет
их длины в отдельном временном файле. Временные файлы удаляются после успешной
сортировки. Vector-обёртки рассчитаны на последовательный запуск.

Для каждого алгоритма есть 7 понятных тестов: массив варианта 9, пустой массив,
один элемент, отсортированный массив, обратный порядок, повторы и `double`.
Для внешних сортировок также проверяются файловый API, вариант 9 в файле и слияние серий.
Всего в проекте 97 тестов и 105 проверок; 15 тестов относятся к варианту 9.
